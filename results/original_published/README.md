These are the result files committed on `main` at 7474c77, preserved unchanged
as the historical record. They are **not** regenerated by any command in this
repository, and `python main.py` no longer overwrites them: it writes its own
tables to `results/` and its structured output to `results/tier1/`.

## How to read them

Three caveats belong with these numbers.

1. **The intervention was broken.** Candidates were pairs of query rows scored
   by support Jaccard, but the intervention masked the edge `i -> j`. Those are
   different objects. Worse, the mask is causal and `i`, `j` were drawn
   independently, so every sample with `i < j` masked an already-absent entry:
   a no-op with delta identically zero, which the `delta <= eps` rule then
   classified as redundant. See F1 and F2 in the main README.
2. **Chance accuracy on this task is 5.0%.** Two of the three CRPA rows sit at
   or near it, so the reported "6x better than naive" compares one partially
   working configuration against two that were not working.
3. **Single seed.**

`table5_routing.txt` reports identical values in all three conditions
(entropy 1.386, which is exactly ln 4, and load error 0.0000). That is F10: the
diagnostic fed the token embedding to every layer's router instead of that
layer's actual input, so it measured nothing.

## Reproducing them

The original code is recoverable and runnable:

```bash
git show 7474c77:model.py > /tmp/model.py    # and so on for each module
```

`--intervention_mode legacy_rowpair` reproduces the original candidate
selection and intervention semantics within the current codebase.
